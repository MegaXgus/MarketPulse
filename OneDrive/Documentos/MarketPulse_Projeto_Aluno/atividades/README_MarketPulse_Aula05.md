# MarketPulse — Aula 05

## Tema
Planejamento técnico e backlog de evolução

## Situação do projeto
O MarketPulse contém decisões e artefatos legados que podem estar incompletos, inconsistentes ou inadequados ao conteúdo desta aula. O aluno deve analisar o estado atual antes de modificar.

## O que o aluno deve fazer
1. transformar achados e hipóteses de requisitos em backlog priorizado de decisões de design;
2. definir critérios de aceitação verificáveis para as próximas entregas;
3. montar quadro no GitHub Projects/Kanban ou equivalente;
4. relacionar cada item prioritário a um risco técnico ou necessidade do MarketPulse.

## Dicas
- Separar tarefa de implementação de decisão de design.
- Evitar backlog composto apenas por nomes de tecnologias.

## Evidências mínimas da entrega
- Issue identificada como `Aula 05`.
- Branch sugerida: `aula-05`.
- Commits com mensagens que expliquem mudanças relevantes.
- README/Markdown da entrega contendo **problema observado, alteração realizada e critério de aceitação**.
- PR ou registro equivalente permitindo revisão do grupo.

## Prazo operacional
O trabalho deve começar em sala. O limite de conclusão é o início da aula seguinte, salvo orientação diferente do professor.
