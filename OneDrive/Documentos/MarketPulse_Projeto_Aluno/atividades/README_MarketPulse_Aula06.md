# MarketPulse — Aula 06

## Tema
Requisitos funcionais, não funcionais e rastreabilidade

## Situação do projeto
O MarketPulse contém decisões e artefatos legados que podem estar incompletos, inconsistentes ou inadequados ao conteúdo desta aula. O aluno deve analisar o estado atual antes de modificar.

## O que o aluno deve fazer
1. reescrever os requisitos vagos de `docs/requisitos_iniciais.md` de forma verificável;
2. incluir requisitos arquiteturalmente significativos de segurança, desempenho, disponibilidade e manutenibilidade adequados a ordens e cotações;
3. criar matriz de rastreabilidade entre requisitos e decisões/artefatos;
4. priorizar os requisitos que influenciarão a escolha arquitetural.

## Dicas
- Expressões como 'rápido', 'seguro' e 'sempre disponível' precisam de critérios observáveis.
- Não escolher arquitetura antes de justificar os requisitos que a pressionam.

## Evidências mínimas da entrega
- Issue identificada como `Aula 06`.
- Branch sugerida: `aula-06`.
- Commits com mensagens que expliquem mudanças relevantes.
- README/Markdown da entrega contendo **problema observado, alteração realizada e critério de aceitação**.
- PR ou registro equivalente permitindo revisão do grupo.

## Prazo operacional
O trabalho deve começar em sala. O limite de conclusão é o início da aula seguinte, salvo orientação diferente do professor.
